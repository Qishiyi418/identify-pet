# 动作切换闪动修复

2026-10-14

原来每段动画各占一张透明画布，切换时通过 CSS 同时淡入、淡出。即使两段中同一位置的人物都完全不透明，过渡中点的实际不透明度也只有约 75%，容易出现人物短暂变淡、露出桌面和闪一下的感觉。

现在由 `src/frame-presenter.js` 在一张可见画布上交接画面：

- 保留当前实际显示的画面，等待下一张可用画面。
- 以 100 毫秒完成透明像素的加权混合，重叠区域保持原有不透明度。
- 快速打断动作时，从正在显示的混合画面接续。
- 解码器短暂等待或循环回跳时保留已绘制的画面；明确重新播放动作时仍立即重绘首帧。
- 跑动翻转、撑伞画布偏移、脚底锚点和缩放沿用现有布局。

源画布继续提供动画帧和 Alpha 点击检测，前台只显示合成画布。额外的动画帧调度只在交接期间运行。动画素材、随机策略和分组播放时长没有修改。

运行本仓库的交接回归测试：

```powershell
npm run test:transitions
```

六项测试覆盖不透明度保持、透明边缘、首帧延迟、连续打断、失效回调和资源释放。本地完整开发工作区另外通过 116 项测试、17 项真实窗口切换检查和 68 项既有桌面检查。真实动作共观察到 61 次交接、9611 帧和约 2019 万个重叠像素采样，没有空白帧或重叠区域异常透明度下降。光栅对照中，旧方式中点 Alpha 为 191，新方式为 255。

该修复针对渲染交接。原素材中明显不同的姿势、比例、道具或颜色仍可能产生轻微跳变，实际屏幕观感由用户确认。
